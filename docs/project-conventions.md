# X-ray 项目约定

本文件是 `/Users/a399/Desktop/data/X-ray` 的唯一项目约定正文。它约束代码、
文档、测试、运行、证据和回退；与它冲突的旧说明以本文件为准。仓库入口文件
`AGENTS.md` 和技能入口 `skills/xray-manager/SKILL.md` 只负责引用本文件并补充
执行入口，不重复维护另一套规则。

## 1. 适用范围与权威文件

文件职责固定如下：

| 文件 | 职责 |
| --- | --- |
| `AGENTS.md` | 仓库级硬边界、Git 安全和代理必须遵守的最小入口 |
| `docs/project-conventions.md` | 项目完整约定，本文件 |
| `skills/xray-manager/SKILL.md` | X-ray 任务启动、实施、验证和收尾流程 |
| `docs/project-ledger.md` | 文件级读写、时间逻辑、命令、验证、复用和回退的追加式记录 |
| `docs/progress.md` | 阶段/门禁/退出码/证据/验收状态 |
| `docs/version-record.md` | 版本、提交、标签、迁移和发布回退索引 |
| `tests/acceptance/matrix.json` | 本地、外部、生产验收边界及状态 |

每次任务只能有一个项目台账。已有 `docs/project-ledger.md` 时追加，不另建
平行台账。台账是证据，不是计划的替代物；写了计划但未实现、未验证的内容
必须保持 `未实现`、`未运行` 或 `阻塞`。

## 2. 项目边界

- X-ray 是独立管理平台。不得从 Shop、`vue-shop-admin`、
  `shop-xray-installer` 或 `archive/` 导入代码、依赖、运行配置、数据库、
  凭据或测试数据。
- `archive/` 只能作为明确的只读历史参考；不得进入 Docker context、包、
  CI、测试、运行时导入或发布产物。
- 不停止、不复用、不覆盖其他项目的进程、端口、凭据、数据库、浏览器会话
  或工作树修改。启动服务前先检查监听者和工作目录。
- 真实 AWS/SWAS 写入、SSH、公网 Google 探测、生产主机、生产 TLS、实例删除、
  静态 IP 释放、真实设备验收和生产发布都需要明确的任务级授权。
- 本地验证只使用专用 PostgreSQL/Redis 和 Fake/Stub provider。容器健康、单元
  测试、浏览器本地验收不能被表述为真实云或生产可用性。

## 3. 任务生命周期

### 3.1 开始

开始时必须：

1. 读取 `AGENTS.md`、本文件、`skills/xray-manager/SKILL.md`、项目台账和相关
   reference；
2. 检查当前分支、提交、工作树、差异、监听端口、依赖版本、当前进度和验收
   产物；
3. 生成或复用 `run_id`，在台账中记录目标、范围、排除项、假设、授权边界、
   风险和回退；
4. 先读后写，禁止凭记忆把目标状态当作当前状态。

### 3.2 定义变更

每个变更必须明确：

- 目标行为和用户可见结果；
- 允许修改的文件、禁止触碰的文件；
- 是否是代码、配置、测试、文档、运行或发布变更；
- 是否有数据库、会话、凭据、Token、云资源或外部系统影响；
- 必须通过的 focused/regression/browser/runtime gate；
- 回退方式和不可逆状态；
- 未授权、无法运行或证据不足的部分。

### 3.3 实施

- 代码行为修改遵循“小改动、兼容接口、先测试后修复或至少补 focused test”。
- 文档/流程修改不强行新增业务测试，但必须执行文档格式、技能校验、边界
  扫描、秘密扫描或对应的静态门禁。
- 每次创建、修改、移动或删除文件都在台账记录操作、原因、范围、工具、用户
  请求/授权、可逆性、前后 hash（可安全计算时）和回退点。
- 不把密码、密钥、Cookie、Token、私钥、原始 URI 或含秘密的异常写入参数、
  日志、截图、报告、URL、localStorage 或台账。

### 3.4 验证

验证按风险分层记录：

1. 静态/只读：`git diff --check`、格式、类型、边界、秘密扫描、技能校验；
2. 单元/集成：focused test、回归测试、迁移检查；
3. 本地运行：专用容器、健康接口、前后端代理、浏览器流程；
4. 外部/设备/测试网/生产：只有授权、完整请求标识、读回证据、时间戳和
   脱敏资源身份齐全才能 `passed`。

状态词固定为：

- `passed`：有可复现命令和证据；
- `failed`：命令执行但未通过；
- `blocked`：缺授权、缺环境或有明确阻断；
- `not-run`：本轮未执行；
- `risky_not_executed`：破坏性或高风险动作因无授权未执行。

不得用“应该可以”“已实现所以通过”“进程存在所以业务验收通过”替代证据。

### 3.5 收尾

收尾必须：

- 追加最终台账事件；
- 运行 `git diff --check`；
- 复核 `git status --short --branch` 和变更范围；
- 将命令、退出码、证据、状态、当前提交/脏树和回退点写入相应台账；
- 说明已完成、未运行、阻塞、外部边界和下一安全步骤；
- 保留用户原有修改，不私自清理、重置或提交。

## 4. 文件读写台账

### 4.1 读取

每次有意义读取至少记录：

`path_scope`、文件范围、目的、工具、时间、脱敏摘要、当前提交/脏树。

大文件或敏感文件只记录范围、hash 或元数据。读取忽略的 `.env` 只能记录
“已加载但未回显”，不得记录值、长度组合、密钥格式或 DSN。

### 4.2 修改

每次写入至少记录：

`operation`、路径、原因、变更摘要、文件类别、工具、授权来源、可逆性、
前后 hash（安全时）、证据和 `rollback_ref`。

删除、覆盖、迁移、会话撤销、凭据轮换、云写入和资源释放必须先确认精确
目标与范围，并单独记录风险和回退。

### 4.3 追加式原则

台账历史不覆盖、不删除、不重排。发现错误时追加一条 correction，引用原
`event_id`、说明原因、给出新结论和验证证据。

## 5. 时间与日期逻辑

- 台账和人类可读记录使用执行机器实际时钟，保存带偏移的 ISO-8601，例如
  `2026-09-25T11:43:47+08:00`；跨机器比对同时使用 UTC `Z`。
- X-ray Django 使用 `USE_TZ=True`：业务时间使用 aware datetime，数据库统一
  保存 UTC；显示层需要时显式转换 `Asia/Shanghai`。
- 任何时间输入必须写明格式和解析规则，并区分缺失、非法、naive、带偏移、
  夏令时歧义和重复时间。
- TTL、会话、挑战、撤销传播、重试和操作超时必须写明边界。默认采用
  `[start, end)`：`now < end` 有效，`now >= end` 过期；若业务不同必须单独
  声明并测试。
- 业务事件排序使用 aware wall clock；持续时间和性能使用 monotonic clock，
  不用墙上时钟相减推断耗时。
- 必须考虑 UTC 偏移、DST、跨日、闰日、时钟漂移、重试和幂等。测试向量至少
  覆盖边界前、恰好边界、边界后、重复执行、缺失时间和非法时间。
- 时间规则的实现、修复或验证必须写入项目台账的 `time_logic` 字段。

## 6. 安全与认证

- 唯一管理员由数据库约束保证；TOTP 由管理员主动选择绑定，不是首次登录的
  前置条件。正常登录时，未绑定管理员以正确密码建立正式会话；已绑定管理员
  必须继续完成 TOTP 或一次性恢复码验证。测试登录旁路只允许明确的本地
  `XRAY_ENV=test` 开关，生产设置必须关闭该旁路。
- 会话只由服务端 session 和 session version 授权；CSRF、TOTP、恢复码、
  step-up、会话撤销和审计必须保留。
- 敏感操作仍要求近期 step-up：未绑定管理员重新验证密码，已绑定管理员
  验证密码与 TOTP；普通密码登录不自动获得敏感操作的近期验证。主动绑定
  TOTP 也要求已登录且完成近期 step-up，绑定密钥和恢复码只在当前页面内存
  中交付。密码或 TOTP 恢复必须作废旧会话与未消费的认证挑战。
- `SecretStore` 按 purpose/AAD/版本隔离 control 与 subscription；密钥只从
  受控运行环境注入，禁止进 Git、URL、参数、localStorage、日志或台账。
- 所有副作用 API 必须带 UUID `Idempotency-Key`；危险动作必须有新鲜、绑定
  目标的 preview 和 step-up。
- 订阅按 token digest 工作，撤销 Token 永久 `410`；不确定的节点撤销必须
  显示风险，不能冒称成功。
- 恢复默认进入 `MAINTENANCE`，完成审计/撤销对账和凭据轮换后才能人工复开。

## 7. 本地运行约定

- PostgreSQL/Redis 使用项目专用 Compose：PostgreSQL `127.0.0.1:55432`、
  Redis `127.0.0.1:56379`；启动前检查端口归属。
- 后端首选 `127.0.0.1:9527`，前端首选 `127.0.0.1:9528`；根目录启动器在
  冲突时自动选择其他可用 loopback 端口，并将实际端口同步到代理、CSRF 与
  就绪检查。不得停止、占用或复用其他进程。
- 前端使用仓库锁定的 Node/pnpm 版本；当前 package manager 约定以
  `frontend/package.json` 为准，不自行升级锁文件。
- 本地 `.env` 可以作为忽略的开发输入，但不能提交、打印或复制到证据；
  `.env.example` 是可审查模板。
- 后台、前端、容器和浏览器进程都必须记录启动/停止、PID/端口、工作目录、
  配置边界和健康证据；停止操作只允许针对已确认属于本项目的进程。

## 8. Git、版本与回退

- 默认直接在用户指定的当前分支工作；本项目当前用户指定分支为 `main`。
  不得为任务自动切换或创建工作分支，只有用户明确要求时才执行分支操作。
  不强推，不硬重置。
- 提交只包含本次相干变更；排除 `.env`、数据库、密钥、钱包、浏览器状态、
  生成的秘密和无关脏文件。
- 阶段发布必须同步 `VERSION`、`CHANGELOG.md`、`docs/version-record.md`、
  `docs/progress.md`，创建注释标签并记录回退点。
- 仅文档/流程约定重写不自动创建新版本；必须明确写入“无版本变化”。
- 应用回退使用阶段标签或 `git revert`；数据库只做兼容迁移和隔离恢复。回退
  不得恢复已撤销 Token、凭据、安全事件、云操作结果或维护屏障。

## 9. 复用与下一步

每个完成条目必须说明：

- 可复用的文件、命令、fixture、证据格式和前置条件；
- 哪些结果只适用于本地 Fake/Stub/容器；
- 哪些外部、设备、测试网或生产步骤仍未运行；
- 使用哪个提交/标签回退；
- 下一步最小安全动作。

如果没有计划复用，也要明确写“本次不复用”，不能省略。
