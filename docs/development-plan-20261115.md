## 2. 范围与执行边界

- 主线支持 AWS Lightsail；应用服务器及云端验收节点均不新增 EC2。
  SWAS 保留既有接口和测试兼容性，真实接入与验收不列入本轮交付承诺。
- 保持 Django/Vben/PostgreSQL/Redis/Celery、当前依赖锁与固定 Xray 版本。
  不引入多租户、普通用户、历史节点接管、跨项目代码或秘密导入。
- 本计划列出的实现路径是未来候选范围，实施前读取具体文件及子目录约定，
  仅修改实际必要文件。新增接口或改变用户操作契约先形成明确设计。
- 本地开发使用专用 PostgreSQL/Redis 和 Fake/Stub；端口通过项目端口管理
  流程确认归属。不得停止别人的监听者、复用不明数据库或关闭端口边界。
- 真实 AWS 写入、SSH、公网探测、生产主机、真实设备、删除、IP 释放和
  生产发布需要当前任务的明确授权。历史窗口不延续到本计划。
- 当前请求仅授权制定计划；以下任务尚未实施，工时是估算。

## 4. 里程碑与执行顺序

1. **M1：本地可复现。** 完成 D1，保留原失败和完整通过两组证据。门禁未恢复前，
   不以旧版 CI 结果代替当前候选验证。
2. **M2：状态可解释。** 完成 D2、D3。管理员可从数量差异定位原因、查看操作，
   启用自动化仍走已有认证和授权边界。若发现已有字段足够，则缩小到 UI 和契约测试。
3. **M3：升级与恢复可验证。** 完成 D4、D5。权限问题尽早提示，执行时再次校验；
   在隔离环境证明升级失败不会误切换，恢复不会使撤销状态复活。
4. **M4：候选可交付。** 完成 D6，提交候选行为清单、证据索引、限制、资源残留
   与应用回退说明。计划建议先按 `0.14.12` 维护候选组织；若新增持久模型或接口
   范围扩大，冻结时再定版本。此处没有预占版本或更改标签。

各任务从 `not-run` 开始；有可复现证据才记 `passed`，失败记 `failed`，
缺环境或授权记 `blocked`，高风险未执行记 `risky_not_executed`。

## 5. 统一实施与验证要求

- 任务启动先追加唯一台账，写清目标、路径、授权、时间规则、风险和回退；
  在当前用户分支 `main` 工作，保持无关修改，未经请求不创建分支。
- 行为修改先写能复现实际问题的 focused test，再做最小改动和相关回归。
  文档修改用静态验证，不添加只复述实现的测试。
- 涉及时序时复用 aware datetime、UTC 存储和明确的显示时区；有效期沿用
  `[start, end)`，覆盖边界前/等于/后、重复执行、时钟偏移与不合法时间。
  运行耗时用 monotonic clock；不延长 step-up、交付内存或云授权有效期。
- 每个工作包运行 `git diff --check`、focused tests、相关 schema/type/build
  门禁；候选冻结后运行完整 `scripts/check-local.sh`。固定 Xray 用例不得跳过
  后仍声称数据面通过。
- 全局静态入口：`python3 scripts/validate-acceptance.py`、
  `bash scripts/check-boundary.sh`、`bash scripts/check-secrets.sh`、
  `python3 scripts/vendor/skill-quick-validate.py skills/xray-manager`。
  Python/Node/pnpm 使用仓库受控版本，系统 `python3` 仅用于兼容的静态脚本。
- 证据保存到 `artifacts/acceptance/<candidate-version>/<run-id>/`；记录
  命令、退出码、精确提交、环境、时间、跳过原因、资源归属与清理结果。
  Token、URI、Cookie、私钥、密码及恢复码不进入产物。
- API 变更同步 OpenAPI 和前端类型；只在确有模型变化时增加兼容迁移。
  发布同步 VERSION、CHANGELOG、version-record、progress，使用注释标签；
  单纯文档计划不升版本。

## 7. 风险、回退与下一步

- 端口修复可能影响测试启动和清理；先检查归属、使用受控独立端口，保留既有卷，
  不通过允许整段临时端口或停止别的服务规避问题。
- 状态诊断可能暴露跨接口定义不一致；先固定计数定义和 fixture，再改展现。
  计数差异不能触发未经用户操作的补池、轮换或资源删除。
- 自动化和升级预检可能产生检查后状态变化；已有执行阶段校验、fence 和幂等
  必须保留，不以“预检已过”跳过重新核对。
- 应用回退使用候选前已验证镜像 digest/config 或对应提交的 `git revert`。
  数据库遵循 expand/contract，永不复活撤销 Token、旧凭据或过期云操作；
  恢复默认 MAINTENANCE。具体生产回退引用在获授权实施时重新核对。
- 本计划本身可撤销新文档并按本轮差异恢复进度说明；台账如需纠正追加记录。
  可复用本计划的 D1–D6 任务定义、现有门禁、测试 fixture 与证据格式。

本机 19 项门禁**。进入实现前补充该任务的文件级范围和验证环境，不启动云资源。
