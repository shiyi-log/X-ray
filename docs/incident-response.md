# 安全事故响应

## 立即动作

1. 记录事故编号、发现时间、操作者和受影响边界，不在工单中粘贴秘密。
2. 调用恢复/安全屏障进入 `MAINTENANCE`，停止 worker 消费；不要删除实例或释放 IP。
3. 对受影响节点执行 quarantine，保留双栈防火墙、旧连接和 provider request ID 证据。隔离结果不明时状态为 `ISOLATION_UNCONFIRMED`。
4. 保存数据库、Operation、审计和独立安全账本的脱敏快照；安全 outbox 落后必须单独报告。

## 分情形处理

- 订阅泄露：先禁用 token 并确认 410，再撤销节点凭据；部分节点失败显示“节点访问撤销未确认”。
- 云凭据泄露：禁用本地账号写入、在 provider 控制台轮换并核对身份；未知写结果先对账，不能重复创建/删除。
- 控制主密钥疑似泄露：保持控制面关闭，轮换云/SSH/MFA 相关数据，不能只重加密原密文。
- 备份恢复私钥泄露：更换 age recipient，重新生成可恢复备份并撤销旧离机访问。
- 数据库恢复或回滚：只恢复到新 `xray_restore_*` 目标，导入最新独立撤销账本；禁止用旧库覆盖当前撤销状态。

## 复开门禁

复开需要审批引用、完整账本序号、所有 token reconciled、所有凭据 rotated、审计 caught up、旧凭据负向探测和新凭据正向探测。真实云、SSH 或公网证据缺失时只可标记 `blocked/not-run/risky_not_executed`，不得用 Fake 或本地 Compose 替代。

事故结束后记录残留实例/IP、费用、需人工删除项、根因、修复提交、镜像摘要、回滚点和后续演练日期。
